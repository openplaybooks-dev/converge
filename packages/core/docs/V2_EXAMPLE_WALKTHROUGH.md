# V2 Example Walkthrough: Screen Generation

This document walks through a complete example of V2's universal unit system generating React screens from a design system.

## Scenario

Generate 5 React screen components from a sitemap using a design system.

## File Structure

```
workspace/
├── .stitch/
│   ├── DESIGN.md          (design system tokens)
│   └── SITE.md            (sitemap with 5 pages)
│
├── .converge/epics/
│   ├── 02-ux-design.ts                    (parent epic)
│   └── 02-ux-design/
│       └── 003-generate-screens.ts        (parent task - yields subtasks)
│           └── 003-generate-screens/
│               ├── 000-screen-{slug}.ts.tpl   (template)
│               ├── 001-screen-home.ts         (generated by AI)
```


## Task Definitions

### Parent Task

```typescript
// .converge/epics/02-ux-design/003-generate-screens.ts

import { taskDef } from '@converge/core';

export default taskDef()
  .id('generate-all-screens')
  .title('Generate All Screens')
  .agent('ui-developer')
  .yields({
    plan: `
      Read .stitch/SITE.md sitemap.
      For each page (Home, About, Services, Blog, Contact):
      1. Instantiate template 000-screen-{slug}.ts.tpl
      2. Replace {slug} with page slug (e.g., "home", "about")
      3. Write as 001-screen-home.ts, 002-screen-about.ts, etc.
    `,
    outputDir: '.converge/epics/02-ux-design/003-generate-screens',
    template: '.converge/epics/02-ux-design/003-generate-screens/000-screen-{slug}.ts.tpl',
    maxTasks: 20,
  })
  .inputs(['.stitch/SITE.md', '.stitch/DESIGN.md'])
  .outputs(['.converge/epics/02-ux-design/003-generate-screens/**/*.ts'])
  .build();
```

## Key Observations

### 1. No Type Switching

Same `Unit` class for parent and children:
- Parent: Has children → delegates
- Child: No children → uses AI

### 2. Data-Driven Behavior

Parent's `.yields()` tells AI how to generate children:
```typescript
yields: {
  plan: 'Create one task per page',
  template: '000-screen-{slug}.ts.tpl',
}
```

### 3. Automatic Child Discovery

Parent doesn't manually create children. V2 automatically:
1. Looks for subdirectory: `003-generate-screens/`
2. Scans for `*.ts` files
3. Loads each as a `Unit`

### 4. Gap Metadata Flows Through

Child tasks inherit context from parent gap:
```typescript
{
  gapKind: 'output',
  taskPrompt: 'Generate src/pages/Home.tsx...',
  taskAgent: 'ui-developer',
  taskInputs: ['.stitch/DESIGN.md'],
}
```

`GapFixer` uses this to execute the task correctly.

### 5. Convergence Loop Works at All Levels

Same loop for parent and children:
```typescript
while (iteration < maxIterations) {
  gaps = findGaps()
  if (gaps.length === 0) return true  // ✅ Converged
  fixGaps(gaps)
}
```

```typescript
else if (level === 'task') { /* ... */ }

// Manual gap detection per level

// 1,796 lines of complexity...
```

### V2 (Simple)
```typescript
// Universal unit
const unit = await Unit.fromPath(taskPath);

// Same method for all levels
await unit.run();

// That's it!
```

## Conclusion

V2's universal unit system demonstrates:

✅ **One abstraction** - `Unit` class works for all levels
✅ **Data-driven** - Behavior from `taskDef`, not code
✅ **Self-organizing** - Children discovered automatically
✅ **Convergent** - Same loop at every level
✅ **Composable** - Tasks nest infinitely

The walkthrough shows how a complex multi-level workflow (parent generates subtasks → subtasks execute) works with just **one class** and **one loop**.

**The key insight: You don't need inheritance when you have data.**
