System Design: Enterprise Async Video Platform

Architecture specification for an end-to-end encrypted async video platform targeting enterprise teams. The design prioritizes zero-knowledge encryption, real-time AI transcription at the edge, and deep integrations with Jira, Linear, and Notion.

Architecture overview
Three-tier architecture: (1) Client SDK with local encryption before upload, (2) Edge processing nodes for AI transcription using on-device models, (3) Cloud storage with encrypted-at-rest blob service. Key invariant: plaintext video never leaves the client device.
Core components
  • Recording SDK — Browser extension + desktop app, WebRTC-based capture, AES-256 encryption before upload
  • Transcription engine — Whisper-based model running on client, produces encrypted transcript alongside video
  • Integration layer — Webhook-based connectors for Jira, Linear, Notion with OAuth2 auth flow
  • Admin console — Team management, usage analytics, compliance audit logs
Technical tradeoffs
Client-side transcription reduces accuracy by ~8% vs server-side (Whisper large vs Whisper small). Mitigated by offering optional server-side processing for non-sensitive content with user consent. Encryption adds 200ms latency to playback start — acceptable for async use case.
Timeline estimate
MVP in 14 weeks: weeks 1-4 SDK + encryption, weeks 5-8 transcription engine, weeks 9-12 integrations, weeks 13-14 compliance documentation. SOC 2 process runs in parallel starting week 6.
Decision requested
Approve the architecture and authorize implementation. Key decision point: accept the client-side transcription accuracy tradeoff, or add 4 weeks for a hybrid processing model.
