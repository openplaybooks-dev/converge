# Redirects

Cloudflare Pages reads `public/_redirects` (a flat text file). Two things
go in it:

1. **Root canonical**: `/docs` → `/docs/getting-started/why-converge`
2. **Legacy aliases**: every entry in `docs/_redirects.json` (owned by the docs playbook) merged in

## File format

```
# Generated by 06-integrate-docs/004-redirects. Do not edit manually.
# Source: docs/_redirects.json (legacy aliases) + canonical entries below.

/docs                  /docs/getting-started/why-converge   301
/docs/                 /docs/getting-started/why-converge   301

# Legacy aliases from docs/_redirects.json:
/docs/getting-started.md   /docs/getting-started/your-first-playbook   301
/docs/why-converge.md      /docs/getting-started/why-converge          301
# ... (all entries from docs/_redirects.json)
```

## Process

1. Read `docs/_redirects.json` — array of `{ from, to, code }` entries.
2. Write `apps/landing/public/_redirects` starting with the canonical `/docs` entry, then each legacy entry as `<from>  <to>  <code>` (whitespace-separated).
3. Note: Cloudflare's `_redirects` paths must match the URL path served, so if `_redirects.json` has paths like `/docs/getting-started.md`, they translate as-is.

## Banned

- Hardcoding entries that aren't in `docs/_redirects.json`. The docs playbook owns the legacy aliases — if a redirect is needed but missing, fix it there first.
- Using regex / wildcard rules in `_redirects` for v1. Stick with literal paths; a future task can add wildcards if needed.
